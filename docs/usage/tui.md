# TUI 使用

本章面向直接在终端中使用 Lucia 的用户。插件版 TUI 只提供 Plugin Host；功能插件由用户显式安装、启用或通过 manifest 指定。

TUI 与官方插件界面统一使用英文，不读取或注入系统语言设置。

## 安装与启动

```bash
bun run install:tui
lucia
```

`install:tui` 会构建插件版 `lucia` 并安装到 Cargo bin 目录，不会安装任何功能插件。启动时会加载 TUI `/plugins` 人工管理且已经启用的插件，并自动扫描 `$LUCIA_HOME/plugins` 与 `$LUCIA_HOME/official-plugins` 的直接子目录；未设置 `LUCIA_HOME` 时，应用目录是 `$HOME/.lucia`。

第一次启动会创建 `$LUCIA_HOME/config.json`。配置不存在或模型密钥不可用时，TUI 使用本地演示模型；也可以显式运行：

```bash
lucia --demo
```

## 配置模型

推荐在配置中保存环境变量名，不保存密钥明文：

```json
{
  "model": {
    "name": "default",
    "provider": "open-ai",
    "base_url": "https://api.openai.com/v1",
    "model": "替换为账号可用的模型 ID",
    "api_key_env": "OPENAI_API_KEY",
    "openai_protocol": "responses",
    "context_window": 200000
  },
  "agent": {
    "max_steps": 0,
    "max_tokens": 4096,
    "stream": true
  },
  "tui": {
    "sessions_dir": "projects"
  }
}
```

设置密钥后重新启动：

```bash
export OPENAI_API_KEY="你的密钥"
lucia
```

字段含义：

- `model.name`：进程内模型服务商的逻辑名称，Agent 通过它选择 provider。
- `model.provider`：适配器类型，支持 `open-ai`、`open-ai-compatible` 和 `anthropic`。
- `model.base_url`：服务根地址；官方 OpenAI 默认使用 `https://api.openai.com/v1`。
- `model.model`：实际发送给服务商的模型 ID，不是本地显示别名。
- `model.api_key_env`：保存密钥的环境变量名。也可使用 `api_key` 明文字段；两者同时存在时 `api_key` 优先。
- `model.openai_protocol`：OpenAI 类服务使用 `responses` 或 `chat-completions`。
- `model.context_window`：用于底栏上下文占比展示和原生自动压缩水位；估算上下文达到窗口的 80% 时开始压缩。未显式配置时使用当前模型的 models.dev 元数据，切换模型时同步更新压缩器。
- `agent.max_steps`：一条用户指令连续执行的 ReAct 步数；交互主会话中 `0` 表示不设置总步数上限。
- `agent.max_tokens`：单次模型响应的最大输出 token 数，是否支持由服务商决定。
- `agent.stream`：是否使用模型流式接口，默认 `true`；设为 `false` 时等待完整响应。
- `tui.sessions_dir`：按项目隔离的会话根目录；相对路径以配置文件目录为基准。
- `tui.events_jsonl`：可选事件日志；相对路径以配置文件目录为基准。

## 终端主题与颜色

界面自动沿用**终端自身的主题**，不读取操作系统的深浅色设置，也不需要手动切换 Lucia 主题：
正文和背景使用终端默认色，成功、警告、错误等使用终端 ANSI 调色板。运行中切换终端主题时，
已有文字也会随终端的默认色与色板更新；具体色相和对比度由终端主题决定。

代码块和引用使用终端底色，以竖线、缩进及语法色区分；diff 保留 `+` / `-` 和红绿语义色。
菜单选中行采用默认前景/背景反色，并保留指示条与粗体，深色、浅色和单色环境均可辨识。
插件 UI 走同一配色出口；插件显式成对声明的前景/背景仍使用对应终端色板槽位。

- 设置非空 `NO_COLOR`，或使用 `TERM=dumb` 时，禁用颜色并保留文字、粗体及反色提示。
- 普通终端使用基础 ANSI 色；只有 `COLORTERM=truecolor` / `24bit` 或 `TERM` 以 `-direct`
  结尾时，首屏头像保留原画 RGB。头像是图像，不随主题改色。
- 全屏交互仍要求 UTF-8 和光标控制能力；`TERM=dumb` 的单色降级不等于支持完全无 ANSI 的终端。

Markdown 标题用粗体和段落间距区分，不附加红色方块。代码块支持反引号与波浪号围栏，
外层长围栏中的短围栏示例不会提前结束代码块；工具执行开始时收起上一段正文的流式光标。

Shell 预览在排版前移除 ANSI 颜色、光标和 OSC/DCS 控制序列，避免可打印残片挤占代码列；
不执行日志中的终端命令。CRLF 归一为换行，单独 CR 作为日志行边界，不模拟进度条覆盖。
标准输出与标准错误分别拼接后展示（stdout 在前、stderr 在后），避免两个流的半行交错；
不额外添加日志行号，编译器自己的行号与诊断竖线原样保留。原始工具结果不改写。
路径超宽时从前缀省略、保留文件尾部，截断不拆开组合字符或 emoji。

## 输入与快捷键

| 操作 | 按键 | 行为 |
| --- | --- | --- |
| 发送 | `Enter` | 提交当前输入；运行中默认排队到本轮结束后整条发送，待发送消息显示在输入框上方，可编辑后重新入队 |
| 立即发送 | `Ctrl+Enter` | 停止当前轮次，等其保存收尾后优先发送完整消息；支持附件和上下文引用，不再等待当前模型响应结束才插话 |
| 换行 | `Ctrl+J` / `Shift+Enter` / `Alt+Enter` | 在输入框中插入换行 |
| 中断、返回或清空 | `Esc` | 运行中请求取消；菜单或子页面返回上一级；主输入区连续双按清空草稿，不会退出 Lucia |
| 中断或退出 | `Ctrl+C` | 运行中只中断本次运行；有草稿时清空草稿；空输入时提示并要求两秒内再按一次才退出 |
| 退出 | `Ctrl+D` | 空输入时按终端 EOF 约定直接退出；输入非空时删除光标右侧字符 |
| 行内移动 | `Ctrl+A` / `Ctrl+E` / `Home` / `End` | 移动到当前逻辑行的行首或行尾 |
| 行内删除 | `Ctrl+U` / `Ctrl+K` / `Ctrl+W` | 删除到行首、删除到行尾、删除左侧一个词 |
| 按词移动 | `Ctrl+←` / `Ctrl+→` | 按词左右移动；`Alt` 组合等价，兼容上报修饰键不同的终端 |
| 滚动历史 | `PgUp` / `PgDn` | 手动滚动消息区 |
| 跳转消息区 | `Ctrl+Home` / `Ctrl+End` | 跳到顶部或回到底部；手动翻阅时也可直接点击输入框上方右侧的提示回到底部 |
| 输入历史 | `↑` / `↓` | 空输入框回填最近提交，继续浏览更早或更新的输入；`Ctrl+P` / `Ctrl+N` 为兼容按键 |
| 进入排队面板 | `Ctrl+O` / 左键单击排队行 | 键盘焦点移到输入框上方的待发送消息列表；点击某一行会直接选中该行 |
| 排队面板内 | `↑` / `↓` → `Enter` | 选择待发送消息并按 `Enter` 发送：空闲时立即开始新一轮并恢复 FIFO，运行中则置顶到本轮之后 |
| 排队面板内立即发送 | `↑` / `↓` → `Ctrl+Enter` | 停止当前轮次并优先发送选中项；保留输入框草稿、附件/引用和其他队列项的顺序 |
| 排队面板内编辑 | `Ctrl+O` | 把选中项取回输入框修改；输入框已有草稿时草稿自动排到队尾，两边内容都不丢 |
| 排队面板内丢弃 | `Delete` | 丢弃选中项；正在发送的队首不可丢弃 |
| 退出排队面板 | `Esc` | 焦点回到输入框 |
| 复制选区 | 左键拖选后 `Ctrl+C` | 释放后底栏提示可复制；按 `Ctrl+C` 写入系统剪贴板并收起选区 |
| 复制回复 | `Ctrl+Y` | 复制最近一条助手回复 |
| 鼠标滚轮与选择 | 滚轮 / 左键拖选 | 滚轮浏览历史；拖选只保留高亮，不会在松开左键时覆盖系统剪贴板 |
| 滚动条 | 消息区最右一列上的竖条 | 内容超过一屏时显示；滑块以半行精度跟随滚动，在轨道上按下或拖动即可定位到对应位置；按住滑块拖动会保持抓取点，拖到底部恢复自动跟随 |
| 工具详情 | 左键单击工具消息 | 工具结果默认紧凑显示；单击展开最多 40 行详情，再次单击收起。编辑类工具（如 `edit_file`）只显示增删行数摘要，不展开补丁正文；`search_files` 的命中按文件分组，路径以工作目录为基准显示一次，行号与命中正文逐列对齐；`teammate_result` 这类成员/子 Agent 结果把报告正文放进预览，默认 8 行，展开后看更多 |
| 切换鼠标捕获 | `Ctrl+T` | 默认开启应用内滚轮、文本拖选和插件点击；关闭后恢复终端原生选择及右键菜单 |
| 切换插件焦点 | `Tab` | 在主输入区与可聚焦插件视图间循环 |

全部快捷键同时接受 `Control` 与 `Command`（终端上报为 `Super`）。macOS 上把
Control、Option 与 Command 互换以贴近 Windows 手感是常见做法，重映射后同一个物理键
到达终端时会变成另一个修饰键；两者语义不冲突，因此一并接受，不要求改回系统设置。
快捷键仍不生效时用 `/keys` 进入按键诊断，它会逐条回显终端实际上报的键名与修饰键，
并说明该组合是否被识别为命令修饰键。注意 `Option`（`Alt`）不是命令修饰键：它保留给
按词移动与换行手势。

输入框会按显示宽度自动折行：长文本折成多行，框高随之增长（最多六行，之后内部滚动），
不再把尾部挤出屏幕。折行优先落在空格处，只把长于一整行的单词按字符断开；CJK 字符按
两列计算，不会把一个汉字切成两半。`Ctrl+A` / `Ctrl+E` 仍作用于逻辑行首尾，折行只影响
显示。

输入框只保留上下两条边框，左右不再有竖线：正文与输入内容左对齐，窄终端里也不会被
两边框挤掉两列。输入框上方固定留着一行状态行：左侧是运行状态与退出确认（如
`✳ Working · 12s · Esc to stop`），右侧是 `↓ N lines · click to jump`。这一行的位置
只由版面决定，日志滚动不会移动它；输入框或底栏变高时随布局上移，完全空闲时它只是一行留白。

输入框下方的模型、上游、思考强度、上下文用量、插件状态、目录和 Git 分支会按可用宽度
自动换行，底栏高度随内容增长或收缩。优先把整个条目换到下一行，超长条目再按字素折行，
不会拆开中文、组合字符或 emoji；换行处不保留孤立分隔符。上下文用量的每个可见片段都能
点击打开 `/context`。窗口高度不足时优先保留输入框和少量正文，超出空间的底栏尾部会裁剪，
放大窗口即可查看。

`Ctrl+C` 与 `Ctrl+D` 都不会在一次按键内结束会话：前者需要在空输入上连按两次并有明确提示，后者只在输入为空时生效。退出待确认时输入框边框与状态行文案会转为危险色。

终端支持键盘增强协议时，`Ctrl+Enter`（或上报为 `Super` 的 `Command+Enter`）用于立即发送；
`Shift+Enter` / `Alt+Enter` 仍用于换行。终端若不能区分 `Ctrl+Enter` 与普通 `Enter`，请在终端中
启用扩展键盘协议或配置发送 `CSI 13;5u`（`\x1b[13;5u`），并用 `/keys` 检查上报结果。

粘贴与拖入按**手势**分流，同一次操作不会被规则互相劫持：

- **复制文件后粘贴**：TUI 回查剪贴板里的文件引用，按引用顺序逐个附加。macOS 读取 `NSPasteboard` 的全部文件 URL，因此多选复制同样可用；Linux 读取 `text/uri-list`。剪贴板的文本表示只有文件名，这条回查是定位文件的唯一途径。
- **粘贴或拖入一个或多个路径**：能作为附件的路径直接替换成引用标签，例如 `/Users/me/src/lib.rs` → `[FILE#1]`，输入框不会同时出现路径与标签；无法附加的路径（目录、超限文本、二进制、音视频等）保留路径文本并说明原因。支持绝对路径、`~/` 前缀、相对当前项目的写法、引号或反引号包裹、终端拖入的 `\ ` 转义，以及部分终端给出的 `file://` URI 列表。一次粘贴多行路径（文件管理器多选后的「拷贝为路径名」）或用空白分隔的多个拖入文件时逐个附加。删掉标签即丢弃对应附件。
- **`/attach <路径> [路径...]`**：手动添加，一行可添加多个文件；已有附件时继续追加。其他斜杠命令仍要求先移除附件。
- **在消息正文里写出路径**：发送时图片与 PDF 无论出现在句子哪里都会附加；文本文件只在路径独立成行时内联，其余真实路径登记为只读授权，供工具按需读取。正文保持原样。

路径能否自动变成附件，取决于模型真正能消费什么：

| 目标 | 行为 |
| --- | --- |
| 图片、PDF（≤ 10 MiB） | 附加为附件，模型原生读取二进制内容 |
| UTF-8 文本（≤ 64 KiB） | 粘贴或独立成行时附加为附件，内容内联进请求；粘贴的纯路径由标签替换，正文中的路径文本保留 |
| UTF-8 文本（> 64 KiB） | 只保留路径，让 Agent 用 `read_file` 按 `offset`/`limit` 分段读取 |
| 目录 | 只保留路径，让 Agent 用 `list_directory` 查看 |
| 音频、视频 | 只保留路径；当前模型协议尚未实现对应内容块 |
| 其他二进制、无法解码的文本 | 只保留路径，内联只会得到一条"内容已省略"的占位说明 |

文本上限刻意远小于 10 MiB 的附件上限：文本附件会以完整内容内联进模型请求，并随会话在后续每一轮重新发送，几十 KB 以上就会长期占用上下文。显式 `/attach` 不受这个 64 KiB 上限约束，那是用户已经确认过的动作，但仍受 10 MiB 单附件上限约束。

单个附件上限为 10 MiB。图片、普通文件和 PDF 在输入框中分别显示为 `[IMAGE#N]`、`[FILE#N]`、`[PDF#N]`。只有整段粘贴的纯路径会被标签替换；正文里的路径文字永远不会被改写——同一段文字可能是一条待执行的命令（`cp a.png b.png`）——附件是额外追加的，附加结果会在消息区提示；被跳过的路径会说明原因。粘贴一条明确的本地路径但文件不存在时同样保留文本，并提示"未找到本地文件"。

只输入（不是粘贴）的路径按普通文本发送；发送时图片/PDF 自动附加，独立成行的文本文件内联，其余真实路径登记为**只读授权**。`read_file` 与 `list_directory` 除工作区外，还可以访问用户在本会话中显式引用过的路径，因此工作区外的大文本、目录和二进制不必先附加就能按需读取。授权在切换会话时清空；`.env`、`.ssh`、`.git` 等敏感路径即使被引用也不会放行，写入类工具仍严格限制在工作区内。图片无法通过工具结果传给模型，只能走附件，所以仍按上面的规则自动附加。

附件按 models.dev 声明的输入模态校验：模型不支持图片输入时会拒绝加入并在消息区说明原因。自动附加遇到该情况时只提示，消息本身照常作为文本发送。每一条提示都只说明一处来源，不会静默丢弃用户复制的内容。

运行中按 `Enter` 提交的输入默认显示在输入框上方排队，每行一条；**尚未启动的队列只在内存中，
不进入模型上下文或持久历史**。实际启动发送时，与手动提交一样立即显示用户消息气泡并先保存输入。
取消或模型报错不会隐藏已提交的用户消息，恢复同一会话时仍可看见；退出时尚未发送的队列不保存。

需要抢先处理时，在输入框按 `Ctrl+Enter`，或按 `Ctrl+O` 进入队列、`↑`/`↓` 选择后按 `Ctrl+Enter`。
应用立即请求停止当前轮次（附件准备也不会推迟停止），待旧轮和保存安全收尾后，发送指定的完整消息。
不会强行丢弃保存中的任务，也不承诺回滚已经发生的工具副作用。准备期间与停止期间均可按 `Esc` 撤销；
已准备好的优先消息会退回待发送队列。重复 `Ctrl+Enter` 不覆盖已有优先消息或新草稿。

排队面板仍支持普通 `Enter`：空闲时发送选中项并恢复剩余队列的 FIFO；运行中只置顶到当前轮之后，
不打断当前任务。`Ctrl+Enter` 只抢先处理指定项，其余队列保持原序并暂停，处理完不会偷偷自动发送。
正在发送的队首不能重复发送、丢弃或取回编辑。

在面板内按 `Ctrl+O` 把选中项取回输入框修改：正文、附件与上下文引用都原样恢复，队列中对应条目移除；
输入框已有草稿时草稿自动排到队尾。`Delete` 丢弃选中项，`Esc` 返回输入框。手动中断后队列保持暂停，
在空闲时普通 `Enter` 发送草稿或队列选中项才恢复 FIFO；等待期间的消息不会混入恢复后的上下文。

### 上下文引用

安装了上下文引用 provider（例如 Eden 插件）后，用户在编辑器里选中一段文字，输入框会**自动**
出现 `[REF#1]` 这样的标签，不需要任何命令或工具调用。发送时标签展开为带来源信息的正文，随该
条消息一起进入模型上下文。

标签和附件一样是输入框里的一段文本：删掉它就是不发送这段引用，同一段选区在选区变化前不会
被自动补回；选区消失时标签也会自行移除。引用只在空闲时拉取——运行中的这一轮对话不会中途
换掉已经带入的上下文。

## 斜杠命令

输入 `/` 会显示 TUI 原生提供的命令和用法。常用命令包括：

- `/resume`：在输入框上方打开会话搜索面板，选中后恢复完整会话。
- `/sessions`：同样打开搜索面板，只读浏览当前项目的会话摘要。
- `/plugins`：打开人工插件管理页；变更只影响新 Session，当前 Session 不热重载。
- `/compact`：请求原生 Context Loader 立即压缩当前上下文。
- `/attach`：把一个或多个本地文件加入待发送附件。

命令名称在本地同步补全，不依赖插件加载状态；默认插件版与纯 Core 版都提供斜杠命令和会话搜索面板。

会话搜索面板出现时，输入框本身就是搜索框：直接输入即可按词过滤（多个词必须同时命中，
标题与会话 ID 都参与匹配），`↑`/`↓` 选择、`Enter` 恢复、`Esc` 关闭并清空搜索词。候选按最近
更新时间降序排列，面板一次最多展示 12 行，命中更多时由标题里的计数提示，靠收窄搜索词继续定位。
命中的检索词在标题里高亮，正在使用的会话带有「当前」标记。

## 会话标题

会话第一次成功回复后会追加一次极小的模型调用，用首问首答概括主题，写成 24 列以内的单行
标题；这样列表里不会只剩下"hi"或一段报错粘贴。该调用复用主 Agent 的模型与路由，关闭工具、
推理与提示缓存，失败时静默保留兜底标题（首条消息首行，最多 60 字）。

标题只写入一次：记录里用 `metadata["title.source"] = "model"` 标记来源，已有模型标题的会话
不再重复请求；旧会话在下一次运行结束后自动补名。`--demo` 模式使用脚本模型，不生成标题。

## 会话行为

普通 `lucia` 启动会创建内存中的空白 Draft，不自动恢复上一次会话。用户发送第一条消息时才
按 revision/CAS 持久化该会话。

会话按启动目录隔离。实际路径为：

```text
<sessions_dir>/<project-id>/sessions
```

不同工作目录生成不同 `project-id`。恢复后，用户消息、助手文本和工具结果会重新显示；system、developer 和 thinking 内容不直接展示。

也可以在启动时显式恢复：

```bash
lucia --resume-latest
lucia --session-id design-review
```

## 插件界面

插件只能返回声明式 UI，不能直接操作终端。停靠视图与输入框上方的常驻架都通过 `Tab` 获得焦点；Dialog 显示时优先接收输入；进入插件子视图后按 `Esc` 返回上一层。Dialog 与宿主原生面板（命令补全、`/plugins`）共用一块底板：贴在输入框上方、横向铺满，只保留一条上分隔线，标题画在线上；插件声明的 `size.height` 表示可见内容行数。`/context` 是只读的信息视图，改用四边圆角边框：标题画在顶部边框上，内容与按键提示都在框内，与下方输入框之间仍留一行空白。

输入框上方的架子由插件自己决定显隐和高度，宿主只负责按内容行数布局：没有内容时整块不占行，内容变多时跟着长高。团队（Teammate）成员架平时收起成一行摘要，`Tab` 聚焦后自动展开成员列表，`Esc` 返回输入后自动收起；展开态 `↑`/`↓` 选择、`Enter` 打开会话、`w` 打开团队工作台、`Space` 折叠，点击成员行与点击摘要行分别等价于前者。计划（Plan）架只在计划未完成时出现，聚焦后汇总行写明 `Enter 详情`，回车与点击都能打开完整计划。这些按键都只在对应架子获得焦点时生效，位置和提示直接写在架子内容里，因此不依赖终端是否上报鼠标。

插件也可以请求宿主打开**原生 Agent 会话视图**（例如 Teammate 成员会话）。这类视图不经过插件逐帧渲染，而是复用主对话界面：Markdown、工具卡片与展开、滚动条、输入盒和状态行都与主会话一致。按键、滚动与工具展开由 TUI 处理；只有用户提交时，才把一条 `submit` 输入回送插件，由插件决定 steering 还是续跑。`Esc` 返回上一层；窄终端会折叠次要按键提示，正文与输入始终保留。

底栏会在启动阶段显示插件加载结果。加载完成后只在仍在加载或存在失败时保留加载状态；插件通过通用 `footer` 展示目标发布的当前模式会按可信插件来源常驻，例如权限模式不会进入对话消息或 Session。

## 退出与故障恢复

使用 `/exit`、`/quit`、空输入上的 `Ctrl+D`，或没有文本选区时连按两次 `Ctrl+C` 显式退出。Lucia 会在正常退出、错误和 panic 展开时恢复 raw mode、备用屏幕和 bracketed paste 状态。

启动时主屏与备用屏幕都会显式清屏，再绘制首帧；运行中仍使用差分绘制，不会逐帧全屏清空。
侧栏显示、隐藏或窗口缩放时，滚动条热区按当前布局重建，旧位置由帧差分擦除。

如果出现残影，可先改变窗口尺寸触发整屏重绘。重绘后消失只能说明屏幕与帧状态曾不一致，
不能单凭这一点判定是 TUI 还是终端问题。反馈时请同时提供 `lucia` 的实际路径、构建版本、
终端名称，以及是否在侧栏变化、缩放或挂起恢复后出现。

开发时可在隔离的本地 demo 会话中检查启动清屏、缩放、括号粘贴、模式切换、颜色降级和退出序列：

```bash
cargo build -p lucia --locked
python3 scripts/pty-render-check.py
cargo build -p lucia --locked --no-default-features
python3 scripts/pty-render-check.py
```

该检查需要 POSIX PTY 和 Python 3，仅使用临时配置与本地演示模型；可通过 `LUCIA_BIN`
指定待测二进制。它验证终端输出协议，不验证终端 GPU/字形渲染；`TERM=dumb` 用例也只确认
该环境变量下能完成协议交互，不表示无 ANSI 能力的终端支持全屏 TUI。

模型或工具问题需要完整事件时使用：

```bash
lucia --events-jsonl ./runs/events.jsonl
```

配置、会话或插件启动异常可先运行 `lucia doctor`。全部启动参数见 [CLI 使用](/usage/cli)。
