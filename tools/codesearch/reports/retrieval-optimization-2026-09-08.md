## 实现边界

- 重排配置为可选 `[rerank]`，不自动复用 Embedding 配置开启新模型请求。
- 继续使用原符号、FTS5/BM25、向量和 RRF；默认重排候选上限 160，正文输入上限 6000 字符。
  文档为路径、符号、签名及同版本正文；概览复用已有结构摘要，不向模型发送人工答案或目标路径提示。
- 返回索引必须完整、唯一、未越界，分数必须有限；无效 JSON、超时、HTTP 错误直接报告 `provider_error`。
  不把失败后的原排序伪装成重排成功，不自动重试延长等待。
- 每个引擎最多并发两次重排请求，总超时 60 秒含排队；响应体上限 1 MiB；禁用 HTTP 重定向；不记录 API Key 或远程错误正文。
- 重排网络等待不持有 SQLite/USearch 锁；组装重新检查代码块是否仍是当前版本。
  诊断在 await 前暂停并移出线程、之后恢复，仍按同次调用记录，不重跑召回伪造阶段证据。
- 不修改 MCP 入参和已有错误码。成功重排会在状态说明中标明模型，完整符号精确命中保留规则继续生效。

## 延迟与失败

最终真实 MCP（36 次成功调用）：中位 6284.5ms，P95 9122.8ms，最大 9410.3ms。
计时包含搜索和模型调用，不包含初始索引或随后逐项 read_code 校验；不是独占环境的生产 SLA 基准。
默认项目与 PHP 补测有部分运行时段重叠，延迟不作为严格的模型算力横向比较。

离线 BGE 重排请求中位约 1558ms；Qwen 中位约 6308ms。Qwen 首次评测曾有一次 120 秒超时，
以及一次约 45.8 秒的成功请求；保留 35 条成功缓存后仅补跑超时题，没有把失败计为成功或快速返回。
因此不默认开启远程重排，也不能保证每次搜索都在十秒内完成。

每题只生成一次真实查询向量，再同时比较 ANN Top-80 与全量余弦排序；不向召回注入真值。

未通过随意扩大 Top-K、改问题、加项目词表或隐藏失败来提高分数。
本轮没有重建这些索引或更换 Embedding 模型，后续应在独立实验中验证框架语境与正文表示。

## 使用

需要环境变量 `SILICONFLOW_API_KEY`。可通过 `--config` 指定
[`codesearch.quality.example.toml`](../codesearch.quality.example.toml)，不必修改原项目配置。
该配置显式启用 Qwen 重排，且 Embedding 输入上限采用 PHP 补测验证过的 6000 字符；
切换配置后重新索引，字符上限不等于服务端精确 token 上限保证。

```sh
cargo build --all-features
target/debug/codesearch index --root /项目绝对路径 --config /本工具绝对路径/codesearch.quality.example.toml
target/debug/codesearch serve --root /项目绝对路径 --config /本工具绝对路径/codesearch.quality.example.toml
```

固定候选实验与最终汇总：

```sh
bun eval/diagnose_real_projects.ts --preflight
cargo build --example replay_context
bun eval/rerank_real_projects.ts 新标签 Qwen/Qwen3-Reranker-8B
bun eval/replay_real_projects.ts 新标签 --require-input
bun eval/report_retrieval_optimization.ts --publish
```

结论是“真实调优集明显改善”，不是“闭眼信”。仍有 6/22 主测试问题及 3/4 PHP 问题没返回关键实现，
未实现功能也可能返回相关代码；目前没有经盲测校准的拒答阈值。
